# Changelog

## v4.0.6
- New: personal notes and pins on tasks - only in this extension, never sent to ClickUp. Every task row has a 📌 and a 📝 right after the task name (they appear when you point at the row, and stay visible once a task is pinned or has notes, e.g. "📝 2"). 📌 keeps the task at the top of its list, with an amber edge, on the dashboard, popup and side panel. 📝 opens the task's details at "My notes", which work like client notes: write, paste screenshots with Ctrl+V, attach or drop files, click a thumbnail to see it big, links are clickable, Edit in place and delete. The notes are backed up with your other extension data (Drive sync); attached files stay on this computer.
- New: notes keep their formatting. Text pasted into a task note or a client note from Claude, ChatGPT, Grok or a web page used to collapse into one run of words; it is now kept as headings, bold, strikethrough, code, nested lists, ✓ / ☐ checkboxes, tables, links and quotes, and saved notes are shown formatted (text copied with an AI's own Copy button, which is already in this format, works too). Notes can now be up to 20,000 characters (was 4,000 for task notes and 2,000 for client notes).
- New: tick checklists and edit notes the way they look. Click a ☐ / ☑ in a saved task note or client note to tick or untick it - it saves at once, no Edit needed. Task notes are now written and edited formatted (no more Markdown symbols): a small toolbar has bold, italic, strikethrough, code, bullet and numbered lists and ☐ checkboxes, Ctrl+B / Ctrl+I work, Enter on a checklist line starts a new box, and a "Markdown" switch shows the raw text if you want it.
- New: ⏰ Remind me on every task note. It opens the reminder card already filled in with the task and the note (and its screenshots), linked to the task so the reminder opens it; the note then shows when its reminder is due ("⏰ Oct 6, 9:00 AM" - click it to see all reminders).
- New: ↻ Refresh in Insights. One button next to Health / Plan / Performance reads the latest from ClickUp: your open tasks (Health and Plan; Plan also the developers' dev tasks behind "Expected reviews") or your tracked-time history (Performance).
- New: change any time in Plan. Click a time under "Tasks with an estimate", "Tasks without an estimate", the reviews or "Expected reviews", or on a day in Day by day, and type your own (45m, 1h 30m, 1.5) - the Planned total, Over/Short and the days update at once, "↺ was 1h 24m" goes back to the automatic time, and 0 leaves a task out. Only the plan changes (nothing in ClickUp); time you track afterwards still counts down from your number, and a new ClickUp estimate replaces it.
- New: create a task in the extension first. "＋ New task" above the task list (dashboard, popup and side panel) opens a form in ClickUp's format - name, the List it goes in (the Lists your tasks are in, or paste a List link), due date, estimate, priority, "assign to me" and a formatted description. It's saved as a Draft that only exists in this extension and shows above your tasks like any other row (with ▸ details, notes, pin and reminders). Nothing reaches ClickUp until you press "Apply to ClickUp" - then it's created in that List, and its notes, pin and reminders move to the real task. If ClickUp refuses (for example no access to the List), the draft stays with the reason. Drafts don't count in your totals.
- Improved: every note writes formatted. Client notes (Clients tab) now use the same formatted editor as task notes - writing a new note and editing one - with the toolbar, ☐ boxes and the Markdown switch; pasting from an AI keeps its formatting everywhere.
- New: formatted comments. The comment box in a task's ▸ details is the same formatted editor: paste an answer from Claude, ChatGPT or Grok and post it - ClickUp gets it formatted (headings, bold, italic, strikethrough, code, links, bullet / numbered / checkbox lists including nested ones, quotes and code blocks), not as a wall of symbols. Comments already on a task are shown formatted in the extension too. In the floating tracker, pasted formatting is kept the same way. If ClickUp ever refuses the formatted version, the comment is posted as plain text instead, so nothing is lost.
- Fixed: the This week card disagreed with Due today on the same day (for example Monday: 32h 12m estimated / 2h 8m tracked against 9h 30m / 2h 25m). The week counted a task spread over several days (start to due date) with its whole estimate on the due day, while Due today counts that day's share; and the week, rebuilt only every half hour, missed the running timer and the latest tracked time. Today's column in This week now uses exactly Due today's numbers and tasks (updated with every refresh), and the other days count multi-day tasks the same way.
- Fixed: automatic updates that never installed by themselves. On many computers Chrome only lets the extension's own tabs use the folder permission ("Allow on every visit"), not the hidden page that installs updates, so every automatic try stopped and an "Update now" notice appeared instead. Now, when that happens, the update installs from a tab opened in the background - the tab you're working in stays in front - which shows "Installing the update…" and closes by itself after a few seconds; then the extension restarts as before. Once that has worked, the "Update now" pop-up isn't shown any more for later versions.

## v4.0.5
- New: ask the search for tasks in plain words. Type something like "tasks I completed last month for Acme Dental" or "Sam's tasks for the upcoming week for Bright Roofing" (Ctrl+K, or the search button): the first result reads back what it understood - completed or due, the dates, the client and the person - and Enter lists those tasks right there with their estimate and tracked time. Each part is a chip you can remove with ✕ to widen the search. People come from your workspace's member list and clients from your tasks, so it only picks names that really exist ("acmedental clinic" finds Acme Dental); it understands dates the way people say them - today, yesterday, "last Friday", "next Tuesday", "on Sep 28", "from Sep 1 to Sep 15", "since Monday", "week of Oct 12", "3 days ago", "2 weeks ago", this/last/next week, month, weekend or quarter, "rest of the week", "end of the month", "last 10 days", "next 2 weeks", "recently", "overdue" and month names ("in November" asked about finished work means last November) - with the context in mind - weeks run Sunday to Saturday like the calendar and the dashboard's week filters (on Sunday Oct 4, this week is Oct 4-10 and last week Sep 27-Oct 3), and on a Saturday or Friday evening "last week" is the week just worked and small typos forgiven ("previos wek", "upcomming"). When a phrase can mean two things it shows the best reading first and the other one as "Or: …" (for example last month vs the last 30 days). Other people's tasks use the workspace Admin token saved in ClickUp setup. It's one ClickUp request per question, reused for 3 minutes, and nothing is sent to any AI service.
- New: Plan expects the review tasks that come back from developers. When a developer finishes a "dev"-tagged task, a short review lands on the tech team - often with no estimate or due date. Plan now looks at the developers' open dev tasks for the clients you work on and reserves one review each, on or after the day that dev task is due, sized by how long your past review tasks took (10 minutes to 1 hour; 30 minutes until there's history). Once the real review task is in your list (same audit code or a similar name) the expectation goes away. It's one light ClickUp read, kept for 30 minutes.
- Fixed: a developer's dev task you're also assigned to no longer counts its whole estimate in Plan - your part is the review, so it counts as review time (a 35h dev task shared with you had made one week show 61h).
- Improved: the calendar is livelier in dark mode - rose weekends, vivid holidays, sky-blue work-from-home days, coloured day numbers and a soft glow on today.
- New: apply a day of your plan to your task list. In Insights › Plan › Day by day, press "Apply to my task list" on a day: the dashboard, popup and side panel then show exactly that day's tasks in the plan's order, with that day's planned time (and the Extra Task share) against your daily target, and a "Your plan for Tue, Oct 6 · Back to my filter" bar. Nothing changes in ClickUp, and it clears itself when the day is over.
- New: colour themes. The light/dark button now opens a small menu: switch light or dark, and pick a palette for each - Classic, Ocean, Forest, Rose, Lavender or Slate for light; Classic, Midnight, Pine, Plum or Mocha for dark. Overdue, warning and done colours keep their meaning in every palette.
- Improved: Plan shows exactly what its total is made of. Target, Planned and Over/Short sit side by side, the bar marks the target, and "What makes up the …" lists every hour in groups you can open - the Extra Task share, tasks with an estimate (estimate minus what's already tracked) and tasks without one (suggested) - adding up to the total. When the week is over, "Doesn't fit this week" lists the tasks left over, so the day-by-day plus that list always equals the total. Days fold open one at a time and every task is one tidy line.
- Improved: suggested estimates also learn from how similar tasks are estimated (open or finished), so far fewer tasks get a rough guess.
- New: everything in Performance is clickable - the four numbers, every week's bar, each day of the 7-hour calendar, the deadline and finished-task bars, the workload weeks and the client bars open a list of the tasks and hours behind them.
- Fixed: the popup could get a sideways scrollbar again. It now has a fixed, roomy width (680px - wide enough for task names, never wider than Chrome allows), its cards can't be stretched by a long task row, the Tracking now row wraps on narrow side panels, and the avatar column hides itself when every task is yours.
- Improved: one calm toolbar at the top of the dashboard, popup and side panel - search, side panel, wrap-up, reminders, notifications, light/dark and the dashboard button are now matching line icons (the reminder count and the muted bell still show). The dashboard is now called Personal ClickUp Manager, with a ClickUp-only description.
- New: Insights has three parts now - Health (what it showed before), Plan and Performance - switched at the top of the tab.
- New: Insights › Plan. Pick this week or next week and see how full it is against your target (working days × your daily target; company holidays left out, the Extra Task's share counted): estimated time, plus realistic suggested estimates for tasks that have none, based on how long similar tasks you finished really took (with the reason shown, and marked "rough" when there's no similar task). If the week is short it lists tasks due later that you could start early - real work instead of padded estimates; if it's over, what doesn't fit. A day-by-day plan orders your tasks so dependencies come first: ClickUp dependencies, earlier steps of the same audit item (ACT-066.S2 before .S3), overdue first, then by due date and priority, and tasks waiting on someone last. Nothing is changed in ClickUp.
- New: Insights › Performance, only for you: days you reached your daily target (a 12-week calendar and the last 4 weeks), average per working day, deadlines met, how long tasks take against their estimates, tasks finished per week, workload ahead (overloaded above 110%), where your time went per client, and the tasks that took much longer than estimated - with charts. Its history is read from ClickUp at most every few hours and kept, so the tab opens straight away without loading.
- New: your weekly Extra Task closes itself. It's a recurring Monday-Friday task, and ClickUp only creates next week's one when this week's is closed - so if it's still open at 5 PM on its due day (Friday), it's marked complete and you get a short notification. If Chrome was closed then, it happens the next time the extension runs. It never closes while its timer is still running (it waits until you stop), never touches one you already closed, and can be switched off in ClickUp setup ("Close my weekly Extra Task…").

## v4.0.4
- Fixed: client sites the admin publishes for everyone (Admin › Client sites for everyone) now also switch Site monitor on the first time they arrive, as the Admin card said - before, the sites were added but nothing checked them until each person ticked "Enable site monitoring". It happens once: anyone who unticks it later keeps it off, and a site someone deletes doesn't come back.
- Improved: Site monitor notifications now say what kind of problem it is: "⚠️ Warning - site blank" (the site answers but the page is empty or a WordPress / database error page), "🔥 Error - server error (HTTP 503)" or "🚨 Critical - site down" (no answer at all). If the problem changes while the site is down you get "Still broken, now …", and when it works again "✅ Back up" with what it went through and for how long. Problem notifications stay on screen until you close them, and clicking any of them opens Site monitor. The Check button notifies too when it finds a change.
- Fixed: the daily "Needs tidying" notification now stays on screen until you click it or close it with its X (it used to disappear after a few seconds), and clicking it opens Insights with the lists it talked about (for example Overdue and Missing an estimate) opened and scrolled to. Clicking it a while after it appeared used to open the plain ClickUp home page instead.
- Improved: the Insights tab shows your last results straight away when you open the dashboard ("Updated 2:10 PM · refreshing…") and updates them in the background, instead of "Loading a health check of your tasks…" every time. Only the very first visit has to wait. If a refresh fails, the last results stay on screen, and it tries again at most once a minute.
- New: blank-page check in Site monitor. A site can answer normally (HTTP 200) and still show nothing - for example WordPress's white screen after a PHP error, where the server sends an empty page. It's on for every saved site automatically: the regular check also looks at the page and marks it ⚠️ Blank page when it's empty, shows a WordPress critical error or database error, or has no visible content at all, with a notification like a site that's down. Pages built by JavaScript aren't mistaken for blank ones. It's still one request per site per check, so client servers get no extra load. With the check on, a server error (HTTP 500+) also counts as down.
- New: notes in Clients are edited where they are. Press Edit and the note turns into a text box in its own place, with Save and Cancel under it (Ctrl+Enter saves, Esc cancels), instead of the browser's little grey popup - which showed a long note as one unreadable line, lost every line break you had typed and could not be scrolled. What you have typed survives the list redrawing itself under you, caret and all, so a screenshot pasted in mid-sentence no longer costs you the sentence.
- New: screenshots show themselves in Clients. A picture attached to a note, or added to a client's files, is now a thumbnail you can actually see, instead of a 📎 screenshot-20261002-084758.png line you had to open in a separate tab to find out what it was. Click one and it opens big over the page with its name and an “Open in a new tab” button; Esc, the ✕ or a click outside closes it again. Other files keep their paperclip chip as before, and a note attachment that is only on another computer (attachments aren't backed up to Drive) says so on the tile rather than showing a broken image.
- New: pin the clients that matter. Every client row has a 📌 - press it and that client jumps to the top of the list with a marked edge, press it again to let it go. Pin several and the newest pin sits on top, with the rest in their usual order underneath. Pins are kept with your settings, so they follow you to your other computers.
- New: the floating tracker's bar now shows today inside the total. When a task has tracked time from an earlier day, a lighter band at the left of the bar is today's share of it, so “6h 50m / 7h” can no longer be read as a day's work when most of it was last week's. Pointing at it says the same thing in words (“Today 1h 2m of 6h 50m on this task”). A task you started and finished today is left exactly as it was - there is nothing to tell apart.
- New: in Insights, every number in the By client table is now a button. If a client has 30 tasks with no estimate, click the 30 and the "Missing an estimate" list below opens showing those 30 and nothing else - same for that client's overdue and blocked counts, and clicking the client name (or its Open count) narrows all four lists to them at once. The table also has a Blocked column now, so you can see at a glance who is waiting on something.
- New: a client picker and a search box above the Insights lists. Pick a client to see only their tasks across all four lists, and type to search within them - the task name, the client and the reason a task is blocked are all searchable, so "waiting on" or part of a page name finds it. Each heading shows how much you are looking at ("Missing an estimate (30 of 55)"), and Clear puts everything back.
- New: the Dashboard's "Worth a look" counts are clickable. Press "3 blocked", "55 no estimate", "2 no due date" or the overdue count and you land in Insights with that exact list already open and scrolled to, instead of having to find it yourself.
- New: while you are editing a note in Clients you can change its files too. Press Edit and every screenshot or file on the note gets an ✕ to take it off, and 📎 Attach (or Ctrl+V, or dropping files on the note) adds more. Nothing is written until you press Save, so Cancel puts the files back exactly as they were.
- New: a web address you paste into a client note is now a link you can click - a Google Doc, a Sheet, anything starting http or https - instead of dead text you have to copy out by hand. Links work both in Clients and where the same notes appear in a task's details, and they open in a new tab.
- Fixed: an Insights list stopped at the first 60 tasks, so a client whose tasks were further down the list could not be found at all. Every list now holds the whole set and still shows 60 at a time, so filtering and searching reach all of them.
- Fixed: Insights sections closed themselves while you were reading. Whenever ClickUp refreshed in the background the whole tab was redrawn, collapsing every section you had opened; your open sections, the client you picked and what you had typed now survive a refresh.
- Fixed: right after starting the day, Due today could show hours of tracked time you hadn't done yet (for example 5h 48m at 8:08 AM). When nothing had been tracked yet today, the extension took that as "couldn't read today's time" and used each task's all-time total instead - for the weekly Extra Tasks, the whole week so far. It now shows 0m until you've tracked something today; the all-time total is only used if ClickUp's time entries really can't be read.

## v4.0.3
- New: an audit you attach to a task (📎 Attach, paste or drop - an HTML file, or any file with "audit" in its name) is now also saved to that client's files in Clients, so all of the client's tasks, Explain and Verify use it without attaching it again. The same file isn't saved twice, and screenshots and other files stay with that one task. (Files added in Clients already showed up in the client's tasks.)
- New: replace an old audit with a new one (for example August's with September's). When you attach a new audit to a task and the client already has one, you can press "Replace <old file>" or "Keep both" right there; in Clients every file has a Replace button too (the new file is read first, so the old one is only removed once the new one is in). With several audits kept, Explain and Verify tell the AI each file's date and that the newest one is the current one.
- New: 🧪 Verify in OpenCode, in every task's details. It copies everything about the task - description, every subtask with whether it's done, comments, links, who it's assigned to, what it waits on - together with the client's audit and notes and a set of rules, ready to paste (Ctrl+V) into OpenCode, Claude Code, Codex, ChatGPT or any AI. The AI is asked whether the task is done, what it needs, what it depends on, how to resolve it step by step and exactly where the change goes, in short bullet points. The client's audit is its source of truth: if no audit is saved for the client (or none of it matches the task), the AI is told to ask you for it instead of guessing. When it can reach the site, it checks only that task's pages, normally and with the cache bypassed (so an unpurged cache doesn't fool it), a few requests at a time and without changing anything.

## v4.0.2
- New: a task you have worked on across more than one day now says how much of its tracked time is from today. Beside the running total - in "Tracking now", on every task row, and in the floating tracker - a small "31m today" pill appears, so "4h 49m" is no longer mistaken for today's figure when it is really everything you have ever put into that task. - New: when the saved sign-in itself is the problem - a password GitHub rejects, a 2FA code it will not accept, a missing or invalid TOTP secret, an account with no username - the daily login stops retrying it altogether and says so on the account, instead of quietly trying again for months. Fix it in Manage and press Run, or log in yourself in the tab it leaves open and press "I logged in"; either one starts it up again.

A person's details are now filled in field by field as ClickUp reveals them, and nothing is ever blanked out - a reply with no name can't erase a name you already had.
- Fixed: a colleague could be missing from the Bulk edit "Whose tasks" list even though ClickUp had them, because the member list was read from a cache while the fresh one was still loading - so pressing the refresh button appeared to do nothing. The list is now read properly on open, and a refresh always shows what was just found. If a read still comes back with fewer people than last time, it says so instead of quietly dropping people.
- New: if someone is still not in the list, type their name in the "Whose tasks" search box. After a moment the extension asks ClickUp directly, and if any of their tasks name them they turn up and can be picked - the user id always comes from ClickUp, never from the typed text.

- Fixed: the Bulk edit "Missing" filter no longer reads as if it were on when it is not. It now says "Not set - show all" instead of "Anything" (which looked like "show me everything that is missing something"), and it filters nothing until you actually pick a kind - so loading Deadline crossed, or any other range, lists every task in it whether or not it happens to be missing a due date, a start date or an estimate. When it is off the dropdown is greyed, and pointing at it says what it is doing. (Superseded by the "Filter missing" tick box above, which is the clearer way to do the same thing.)
- New: "By tag" is now a list of every tag in your ClickUp workspace, not a box to type into. Pick the tag from the dropdown and the tasks load; the names come from ClickUp itself, so the spelling is always the one ClickUp matches on and there is no mistyped-tag dead end. The Load button re-reads the tag list, for tags you have added in ClickUp since the tab was opened.
- New: a workspace Owner or Admin can now bulk edit other people's tasks. A "Whose tasks" search box at the top of Bulk edit lists you and every other person in the workspace - type a name or part of one (or an email) to find them, then click the name; a plain <select> stopped being usable at a few dozen names. Pick someone and the whole card switches to them: every date range and the tag filter then list only that person's tasks, the confirmation says whose they are, and the comment on each task starts with who made the change ("Bulk edit by Dipson - Due date changed to ..."). Changing person clears the ticks and the list, so a change meant for one person can never land on another's, and Apply still only touches the rows you ticked. A plain member sees a note saying why the search box is not there; if your own role is member-level, save a workspace Owner or Admin token in ClickUp setup to unlock it. Your own tasks are unchanged, and the token stays in the background - it is never handed to the page.
- Fixed: people missing from "Whose tasks". The list is now read from ClickUp's workspace member directory - every user, with their role, guests included - and it is read with the workspace Admin token when one is saved, so a colleague whose work is older, or who is not in the team you happen to be in, is no longer left out. The ↻ button next to the search box re-reads the list if somebody is still missing.
- New: Bulk edit can work by tag. Pick "By tag", choose a tag, and every open task with that tag is loaded - not just the ones that happen to be due in a date window, so a task with no due date at all is finally in reach.
- New: a batch change can explain itself. Give a reason - for example "the client asked to push it a week" - and the same comment is added to every task you change, written as "Due date changed to Mon, Oct 12 because the client asked to push it a week" (the wording follows the kind of change: status, priority, estimate, start date). You see the exact text before you apply it, and can write the comment yourself instead. Only the tasks you ticked are changed and commented on; a comment is added after the change, so a task whose change failed is never commented on, and a comment that ClickUp rejects is reported rather than losing the change. Untick the box to change without commenting. Comments can't be undone (the Undo button still puts the old values back).
- New: a "Select none" button next to "Select all shown", for when the wrong rows got ticked. The count line also says which tag is loaded.
- New: a daily "needs tidying" reminder, so the things Insights finds do not wait for you to go looking for them. Once a day - 2:00 PM to begin with - you get one short summary of what is overdue, missing an estimate, missing a due date or blocked, naming the tasks and saying why ("Overdue: Update the docs (5 days late)", "Blocked: Website redesign (waiting on Rigo)"). When a task that was blocked yesterday is free again, you also get "Dependencies resolved - you can continue Website redesign and close it.", so the last nudge before you close it is the useful one. Click the notification or its Open Insights button and you land on the Insights tab that produced it. It says nothing at all when there is nothing to tidy, never fires at a weekend or a company holiday, and it respects the pause and mute you already have in the bell menu.
- New: you choose what the summary says and when. In Options, ClickUp setup, Reminders, "Daily 'needs tidying' summary at" sets the time, which days it may fire (weekdays to begin with), which of the four lists to mention (overdue, no estimate, no due date, blocked) and how many tasks each line names. It can also tell you about a resolved dependency, is listed in the bell menu next to the other reminders, and has a Preview now button that posts the real summary without spending the day's one shot - and shows a clearly marked sample when your board is clean.
- Improved: the open-task list behind the Insights tab and Bulk edit is now fetched by one shared function in the background, so the reminder and the tab can never disagree about which tasks are overdue, unestimated or blocked (a test runs both over the same fixture to keep it that way). It reads the same list the tab already used, once a day, and adds no extra work for ClickUp.
- New: new versions now install themselves straight away, whatever you are doing. Before, an update waited for a "quiet moment" - the popup and side panel closed, or you away from the keyboard - so anyone who keeps the dashboard or the side panel open all day could be told "update available" for days and still be on the old version. It now installs within a minute or two of a new version being published. The side panel or popup closes while the extension restarts, and any page you had open comes back on its own.
- Fixed: automatic updates no longer give up. If an install attempt failed, it now retries after about 45 seconds, three times, and then every 30 minutes for as long as it takes, instead of stopping for good after four tries and leaving you with just a notice.
- Improved: the message under "Install updates automatically" now says what is really happening instead of talking about quiet moments, and if an automatic install keeps failing it says why and that it is still retrying.
